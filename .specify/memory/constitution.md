# Overstory constitution

This repository inherits the [organization constitution](https://github.com/Knuckles-Team/pipelines/blob/main/.specify/memory/constitution.md) version 1.6.0. Every article of that constitution applies here. This file adds only the rules and limits of this repository.

**Inherits**: organization constitution v1.6.0 | **Version**: 1.4.0 | **Ratified**: 2026-10-31 | **Last amended**: 2026-11-28

## Organization standards

- [Spec standard](https://github.com/Knuckles-Team/pipelines/blob/main/reference/spec-standard.md): one owning spec per capability, computed states, `Spec:` trailers.
- [Ecosystem boundaries](https://github.com/Knuckles-Team/pipelines/blob/main/reference/ecosystem-boundaries.md): which repository owns which requirement.
- [Wording standard](https://github.com/Knuckles-Team/pipelines/blob/main/reference/ste.md): sentences of 20 words or fewer, with `must`, `should`, or `may`.

## Repository articles

### R-I. The browser shows; arbora decides

Overstory presents and takes input. It reads data and sends commands only through the arbora client. It computes no decision and imports no engine, harness or other interface package.

**Enforced by:** [Ecosystem boundaries](https://github.com/Knuckles-Team/pipelines/blob/main/reference/ecosystem-boundaries.md), overstory row and forbidden-import matrix.

**Plan check:** Does every data access in the change go through the arbora client?

### R-II. No fabricated data in the interface

A view shows real served data or an honest empty, loading or error state. It never shows invented values.

**Enforced by:** Pre-commit hook `no-fabrication-gate` (`scripts/no_fabrication_gate.mjs`).

**Plan check:** Does each new view show served data or an honest state?

### R-III. The frontend type-checks, lints and builds

The TypeScript sources pass the type check, lint and build before a change lands.

**Enforced by:** Pre-commit hooks `typecheck`, `lint`, `eslint-staged` and `pnpm-build`; `eslint.config.ts` and `tsconfig.json`.

**Plan check:** Does the change pass the type check, lint and build?

### R-IV. The full operator surface is WebMCP

Every operator-facing capability of an app must be exposed as a WebMCP tool. City building, navigation and view control are no exception. The tools register on the app's own page and retire with it. They dispatch through the same action seam as the UI. A capability reachable only from the UI is incomplete.

**Enforced by:** the app surface's `webmcpPageIds` declaration, the per-app bound tests (tool surface, registration, dispatch parity) and the plan check below.

**Plan check:** For every new operator-facing capability, does a WebMCP tool reach it through the same dispatch as the UI?

### R-V. The city engine belongs to arbora-city

The city engine, its scene library, its asset kit and its world rows are owned by the arbora-city repository and reach overstory as the `arbora-city` package. Overstory owns only the host: the route and surface, the navigation, the WebMCP tools, the gateway that carries the package's listed Arbora operations, and the response headers that isolate the city page. No new engine, scene or kit work lands in `src/apps/city/core/`, `src/lib/scene3d/` or `scripts/asset-kit/`; it goes to arbora-city's specs. The cutover row deletes those paths.

**Enforced by:** OVERSTORY-CITYHOST-R008 and its bound test `scripts/city-cutover.test.mjs`.

**Plan check:** Does this change touch engine, scene or kit code? If so, is it filed in arbora-city instead?

### Game principles (the city)

These ten principles bind every row of `specs/arbora-city/` while the city code lives here. The cutover of OVERSTORY-CITYHOST-R008 deletes this section; the arbora-city constitution then governs the city. Each principle names its enforcing row and its plan check.

### R-G1. The city is a projection

Every city component derives from a graph fact through one declared mapping registry (class to archetype). No user, business, product or connector is named in game code.

**Enforced by:** OVERSTORY-CITY-R035 and its bound test `mapping.test.ts`.

**Plan check:** Does each new component come from a registry entry, with no per-kind code?

### R-G2. Graph to city

Nodes become places. Edges become roads. Activity becomes traffic. Memory becomes the Hall of Records.

**Enforced by:** OVERSTORY-CITY-R035, R036, R037 and R038.

**Plan check:** Which graph fact does the new visual show, and through which row?

### R-G3. Deterministic growth

The same graph and the same seed must give the same city. Growth rules are declared data and are testable.

**Enforced by:** OVERSTORY-CITY-R039 and its bound test `growth.test.ts`.

**Plan check:** Does the change draw only from the seeded generator, never from `Math.random` or the clock?

### R-G4. The user owns the city

The city is generated by default and is fully customizable. User edits form a persistent layer that regrowth never overwrites. Any area can be reset to its derived form.

**Enforced by:** OVERSTORY-CITY-R032 and R040.

**Plan check:** Does regrowth still respect every pinned edit?

### R-G5. One door for data

All city data comes through Arbora. Nothing is synthesized and then shown as live.

**Enforced by:** OVERSTORY-CITY-R003, R010, R044 and constitution R-II.

**Plan check:** Is each element labelled simulated or live by the bus, and never by the caller?

### R-G6. Work happens in the world

The city and the web UI do the same work and stay in parity. Anything one can do, the other can do.

**Enforced by:** OVERSTORY-CITY-R034 and R043.

**Plan check:** Does a WebMCP tool and a web UI path reach the new capability?

### R-G7. Generate first, within budget

Assets are generated from rules and parameters. The budgets are gates. Authored assets are the exception and pass the license gate.

Arbora City must sustain at least 60 FPS at 1× on the integrated-graphics reference profile defined by the City spec. Debug mode displays measured FPS and flags a missed budget. Release acceptance uses recorded frame times from the reference hardware.

**Enforced by:** OVERSTORY-CITY-R024, R028 and R041.

**Plan check:** Could a rule generate this asset? If not, which byte budget covers it?

### R-G8. Fun is a requirement

Each pillar has a competency question that a test or playtest answers: building visibly changes the system, the city grows when the work grows, places are worth exploring, the city sounds right at every zoom level, and the world keeps the user's time of day.

**Enforced by:** OVERSTORY-CITY-R045 and its bound test `competency.test.ts`.

**Plan check:** Which competency question does the change serve?

### R-G9. Original identity

The art direction, the names, the audio and the assets are our own. Third-party assets enter only through the license gate and leave when a generated equivalent lands.

**Enforced by:** OVERSTORY-CITY-R046 and its bound test `identity.test.ts`.

**Plan check:** Is every name, sound and asset original or license-gated?

### R-G10. Assets prove themselves before shipping

An asset is not accepted on the authority of its author. The pipeline measures transforms, extents, ground contact and budgets. A multi-angle review render signs off each authoring stage. A fix re-exports every family it touches. A stale asset never ships.

**Enforced by:** OVERSTORY-CITY-R048.1 and R048.2 with the export QA report, the asset-QA budget tests and the [asset-pack authoring protocol](../../specs/arbora-city/asset-pack.md#asset-authoring-and-validation-protocol).

**Plan check:** Which measurements and review renders prove each new asset is correct?
