# OVERSTORY-CITY requirements

| ID | Requirement | Verification |
|---|---|---|
| `OVERSTORY-CITY-R001` | **City AppSurface and route wiring.** The city is a hosted app under `/apps/city`. Its `AppSurface` declares `id: 'city'`, its routes, capability `app:city`, and an empty WebMCP/Atlas set for this delivery; it registers in `APP_SURFACES`. The one route `/apps/city` lazy-loads the city page. Caller chain: `src/App.tsx` mounts every route generically → the `ROUTES` registry in `src/lib/nav-registry.ts` → `APP_SURFACES` in `src/apps/index.ts` → the `AppSurface` record in `src/apps/city/surface.ts`. Shape: `src/apps/city/surface.ts` (reuse `appCapability` from `src/lib/apps/contract.ts`), `src/apps/city/routes.ts` (one `RouteDef`, section `apps`, path `/apps/city`, capability `app:city`), registration appended to `APP_SURFACES` in `src/apps/index.ts`. Depends: none. | `src/apps/city/__tests__/surface.test.ts::city` passes (route literals satisfy `surfaceProblems`; registered through the one route registry). |
| `OVERSTORY-CITY-R002` | **Fleet-driven connector district.** The connector catalog is the Arbora fleet, not a curated list. Each fleet server except the arbora core maps to exactly one named plot: `packStatus 'served'` → built online building; `packStatus 'registered_unpublished'` → planned plot. The district sizes to 78 plots (6 columns × 13 rows) so the current catalog (74 connectors) always fits. Tools on a building come from the served tool list only. Caller chain: `CityPage.tsx` boot → `fleetToConnectors` in `src/apps/city/core/ecosystem.ts` (maps the normalized fleet shape of R003 onto `Building` records) → district plots in `src/apps/city/core/layout.ts`. Shape: `fleetToConnectors`, `CONNECTOR_DISTRICT`, `CORE_LANDMARKS` in `src/apps/city/core/ecosystem.ts`; plots derived from `CONNECTOR_DISTRICT` in `src/apps/city/core/layout.ts`. Depends: OVERSTORY-CITY-R003. | `src/apps/city/__tests__/ecosystem.test.ts::fleetToConnectors` passes (7 served → 7 online, 67 registered → 67 planned, arbora core excluded, plot count 78 ≥ catalog). |
| `OVERSTORY-CITY-R003` | **Live fleet through the host.** The host route `GET /api/apps/city/fleet` calls the served Arbora operation `fleet.catalog.list` as the bound actor and returns a strict normalized shape: per server — name, served tool count, `packStatus`. The browser never contacts Arbora directly. The host caches the read for 60 s. An absent operation or unreachable engine answers 503 with a stated reason; a typed refusal passes its code through. Caller chain: `GET /api/apps/city/fleet` → `build_city_router` in `agent/overstory/apps/city/router.py:50` → `CityGateway.fleet()` in `agent/overstory/apps/city/gateway.py:118` → the injected host invoke (`served` operation, wired in `default_apps()` of `agent/overstory/apps/__init__.py`) → the served operation `fleet.catalog.list`. Shape: `agent/overstory/apps/city/router.py` (reuse `host.invoke_operation` through the injected `invoke` callable, the `_ERROR_STATUS` mapping and `AppBackend` registration in `agent/overstory/apps/__init__.py`); the city app is `available` — it degrades to `SIMULATED` (R014) instead of hiding. Depends: none. | `agent/overstory/__tests__/test_city_app.py::test_the_fleet_route_serves_the_whitelisted_catalog` passes (catalog shape over a fake gateway, 503 on unavailable, 60 s cache, status route, typed refusal passes through). |
| `OVERSTORY-CITY-R004` | **Seven core landmarks.** Exactly one landmark per core platform component: Arbora, Medulla, Meristem, Overstory, Tuig, Axil, Scion SDK. Each carries a nameplate, a role line, and internal locations (rooms) shown in the inspector. Caller chain: `CityPage.tsx` boot → `CORE_LANDMARKS` in `src/apps/city/core/ecosystem.ts` → fixed positions in `src/apps/city/core/layout.ts` → landmark scene in `src/apps/city/core/render3d.ts`. Shape: `CORE_LANDMARKS` in `src/apps/city/core/ecosystem.ts` (7 records with `rooms[]`); fixed positions in `src/apps/city/core/layout.ts`. Depends: none. | `src/apps/city/__tests__/ecosystem.test.ts::core` passes (7 landmarks, each with a name, role and ≥1 room). |
| `OVERSTORY-CITY-R005` | **Pinned character population.** Every character is a low-poly GLB humanoid from a pinned, permissively licensed asset pack. At startup the city contains exactly 14 AI agents and 3 human operators, each a distinct pinned model. Caller chain: `CityPage.tsx` boot → `ROSTER` in `src/apps/city/core/ecosystem.ts` → `initSim` spawn in `src/apps/city/core/sim.ts`. Shape: 18 pinned GLBs (17 riders + 1 placeholder cube) under `public/city-assets/riders/`; roster in `src/apps/city/core/ecosystem.ts` (`ROSTER`); `src/apps/city/core/sim.ts` spawns the 17 characters on `initSim`. Depends: OVERSTORY-CITY-R013. | `src/apps/city/__tests__/sim.test.ts::boot` passes (17 characters, 14 AI / 3 human, distinct riders). |
| `OVERSTORY-CITY-R006` | **Agent lifecycle in the simulation.** Each AI agent runs idle → tasked → traveling → working → committing → idle; every transition emits a typed event on the shared bus. Each task targets one building; while an agent works, the building shows activity; task tool calls name the building's tools. Each agent carries a context budget that rises with tool calls; at 85% or more the agent travels to the knowledge vault, compacts, and resumes below the threshold. Caller chain: the `CityPage.tsx` frame loop → `tickSim` in `src/apps/city/core/sim.ts` → the character state machine → typed events on `src/apps/city/core/events.ts`. Shape: `src/apps/city/core/sim.ts` (character state machine, task pump, `context.compacted` at the 85% threshold); events in `src/apps/city/core/events.ts`. Depends: OVERSTORY-CITY-R005, OVERSTORY-CITY-R010. | `src/apps/city/__tests__/sim.test.ts::SC-002` passes (full chain under deterministic ticks ≤ 60 real s at 1×; budgets stay in [0,100]). |
| `OVERSTORY-CITY-R007` | **Human operator behavior.** Human operators patrol. One operator dispatches a task to an idle agent when the page requests it. One operator resolves pending approvals at the gate. Caller chain: the dispatch/approval controls in `src/apps/city/core/ui.ts` → `dispatchTask` and gate approval resolution in `src/apps/city/core/sim.ts` (emits `task.pending_approval` → `task.approved`). Shape: `ROSTER` kinds in `src/apps/city/core/ecosystem.ts` (3 humans with `patrol`/`dispatch`/`gate` duties); `src/apps/city/core/sim.ts` (`dispatchTask`, approval resolution). Depends: OVERSTORY-CITY-R006. | `src/apps/city/__tests__/sim.test.ts::approval` passes (dispatch at boot succeeds; approval cycle emits both events; refused dispatch emits a queued event). |
| `OVERSTORY-CITY-R008` | **Connector construction and publication.** A connector building rises from a planned plot: construction streams `construction.progress` milestones (every 25%), completes within 30 real seconds at 1×, and the building becomes online with a nameplate; its tools become available to agents and the first agent visit lands within 2 real minutes. In `LIVE` mode a newly served pack is reflected on the next fleet refresh with the same construction sequence. Caller chain: the onboard control in `src/apps/city/core/ui.ts` → `onboardConnector` in `src/apps/city/core/sim.ts`; live reflection diffs the refreshed fleet against the world in `src/apps/city/components/CityPage.tsx`. Shape: `src/apps/city/core/sim.ts` (`onboardConnector`, `world.firstVisit` grace); live reflection in `src/apps/city/components/CityPage.tsx`. Depends: OVERSTORY-CITY-R002, OVERSTORY-CITY-R006. | `src/apps/city/__tests__/sim.test.ts::SC-003` passes (construction ≤ 30 real s; first visit ≤ 2 real min; no-empty-plot refusal emits a queued event). |

Caller chain: `tickSim` in `src/apps/city/core/sim.ts` (night factor, sleep/wake, task pump pause) → lighting in `src/apps/city/core/render3d.ts` (sky, lamps, window emissive map). Shape: `src/apps/city/core/sim.ts`; lighting in `src/apps/city/core/render3d.ts`. | `OVERSTORY-CITY-R013` | **Pinned asset verification.** Every shipped character asset is pinned in `public/city-assets/assets.lock.json` with the source commit, sha256 and byte count. | `OVERSTORY-CITY-R014` | **Mode: live fleet, simulated fallback.** When the host serves the fleet (R003), the city runs in `LIVE` mode with fleet data from Arbora. The two sources are mutually exclusive and the active source is always shown. City activity (agents) remains the deterministic simulation in both modes in this delivery. Caller chain: the mode decision in `src/apps/city/components/CityPage.tsx` (fetch `/api/apps/city/fleet` through `src/apps/city/api.ts`; fall back to `FLEET_SNAPSHOT`) → badge and banner in `src/apps/city/core/ui.ts`. Shape: mode decision in `src/apps/city/components/CityPage.tsx`; badge/banner in `src/apps/city/core/ui.ts`; bundled snapshot in `src/apps/city/core/ecosystem.ts` (`FLEET_SNAPSHOT`, capture 2026-11-15).
