| `OVERSTORY-CITY-R002` | **Fleet-driven connector district.** The connector catalog is the Arbora fleet, not a curated list. | `OVERSTORY-CITY-R003` | **Live fleet through the host.** The host route `GET /api/apps/city/fleet` calls the served Arbora operation `fleet.catalog.list` as the bound actor and returns a strict normalized shape: per server — name, served tool count, `packStatus`. The browser never contacts Arbora directly. The host caches the read for 60 s, keyed by the verified principal and tenant — no caller is ever served another caller's view. A cold read is single flight: concurrent cold boots share one in-flight read instead of repeating the fan-out, the read runs as one real asyncio task with the waiters awaiting it through `asyncio.shield` (a cancelled caller never strands the shared read or cancels it for everyone), and the in-flight entry is cleared in `finally` so no state survives a failure. The whole fresh read — catalog listing plus the per-pack tool-name fan-out — is bounded by an overall 30 s deadline; exceeding it answers the unavailable 503 with a stated reason. The catalog read paginates by cursor (`limit: 100`, following `next_cursor`, safety cap ten pages) so a paged catalog is never truncated. The per-pack tool-name fan-out runs concurrently under a concurrency cap (8 in-flight upstream reads) with a per-call timeout (5 s), filtered by server (`servers: [name]`, `kinds: ['tool']`, `limit: 12`) rather than free text; a typed refusal or timeout on one pack degrades that pack's tool list to empty and the rest of the read stands, while an absent operation or unreachable engine fails the whole read with the stated 503 and any other typed refusal passes its code through. Caller chain: `GET /api/apps/city/fleet` → `build_city_router` in `agent/overstory/apps/city/router.py:50` → `CityGateway.fleet()` in `agent/overstory/apps/city/gateway.py:118` → the injected host invoke (`served` operation, wired in `default_apps()` of `agent/overstory/apps/__init__.py`) → the served operation `fleet.catalog.list`. Shape: `agent/overstory/apps/city/router.py` (reuse `host.invoke_operation` through the injected `invoke` callable, the `_ERROR_STATUS` mapping and `AppBackend` registration in `agent/overstory/apps/__init__.py`); the city app is `available` — it degrades to `SIMULATED` (R014) instead of hiding. Depends: none. | `agent/overstory/__tests__/test_city_app.py::test_the_fleet_route_serves_the_whitelisted_catalog` passes (catalog shape over a fake gateway, 503 on unavailable, 60 s principal-scoped cache, cancellation-safe single-flight cold boot, cursor pagination of the catalog read, 30 s overall fresh-read deadline, per-pack typed refusal degrades only that pack, bounded concurrent fan-out with per-call timeout, status route, typed refusal passes through). |

| `OVERSTORY-CITY-R013` | **Pinned asset verification.** Every shipped character asset is pinned in `public/city-assets/assets.lock.json` with the source commit, sha256 and byte count. The app verifies every pinned file at startup (fetch once, hash, compare) and surfaces a typed `asset.failed` event for any mismatch after one retry; the verified bytes are reused by the renderer so a pinned file costs exactly one request. The gate is honoured at render time as well as at startup: the renderer consumes only verified, pinned bytes, and a refused or hash-mismatched pin renders a labelled placeholder and never falls through to an unverified fetch. The lockfile carries a per-file `license` and a top-level `license_allowlist`; startup verification refuses a pin whose license is outside the allowlist — licensing is a gate, not a note. Every locked asset also passes automated QA against the stated budgets (triangles ≤ 4000, materials ≤ 16, texture size ≤ 2048 px, bounds within the stated range) with a rendered turnaround thumbnail on file for human review; a failing asset never enters the lock. Generated assets (R024) record the generator model's licence terms beside the hosting repository's. Caller chain: startup verification in `src/apps/city/components/CityPage.tsx` → `pinBytes`/`pinnedBytes` in `src/apps/city/core/assets.ts` → placeholder fallback in `src/apps/city/core/render3d.ts`. Shape: `src/apps/city/core/assets.ts`; verification in `src/apps/city/components/CityPage.tsx` before sim init. Depends: none. | `src/apps/city/__tests__/assets.test.ts::lockfile` passes (pins 18 files with licenses inside the allowlist; hash match pins; mismatch refuses after retry; QA budgets hold; byte cache serves one fetch). |
