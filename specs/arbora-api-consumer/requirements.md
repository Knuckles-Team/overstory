# OVERSTORY-API requirements

| ID | Requirement | Verification |
|---|---|---|
| `OVERSTORY-API-R001` | **Generated Arbora API client with typed decisions and confirmation flows.** Overstory generates a versioned TypeScript client and a single invoke adapter from the Arbora API schema. It migrates decisions, Markets/apps pages and WebMCP tools to call the client. The console confirmation page sends only the exact server-issued plan reference. That reference completes a previewed effect. Caller chain: the decision, Markets and WebMCP pages and the console confirmation page → `src/lib/arbora-api/invoke.ts` → the same-origin host in `agent/overstory/server.py` → the served Arbora operation. Shape: `invoke(op, input)` and `ConsoleConfirmView` in `src/lib/arbora-api/` and `src/lib/nav-registry.ts`, reusing `identity.ts::confirmedStepUpUrl`. Test: `src/lib/arbora-api/__tests__/invoke.test.ts::uses the verified cookie session and validates the result`. | Contract tests against the generated client plus positive and negative effect tests on the confirmation flow verify this. |
| `OVERSTORY-API-R002` | **Typed ontology, graph, Atlas and object-set operations replace host routes.** Generated Arbora operations replace the ontology, graph, Atlas and object-set route blocks in overstory's api_extensions.py. They also replace the corresponding src callers. The operations preserve tenant scoping, purpose context, cursor pagination and existing error semantics. Caller chain: the ontology, graph, Atlas and object-set views → `src/lib/arbora-api/ontology.ts` and the generated client → `invoke.ts` → the served Arbora operation. Shape: typed operation wrappers in `src/lib/arbora-api/` that replace the blocks in `agent/overstory/api_extensions.py`. Test: `src/lib/arbora-api/__tests__/ontology.test.ts::validates a well-shaped class page`. | Cross-surface fixture tests and browser tests covering each migrated route family confirm parity with the prior behavior. |
| `OVERSTORY-API-R003` | **Remaining domain routes migrate to generated operations with a route census (rollup).** Split into `OVERSTORY-API-R003.1` (route-census typed model) and `OVERSTORY-API-R003.2` (route-census data file and lint rule), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `OVERSTORY-API-R003.1` | **Route-census typed model.** A typed `RouteCensusEntry` model with a strict disposition enum records each route's owning operation. It refuses a `generated-operation` row that omits its owning operation. Caller chain: route-census.ts `RouteCensusEntry` validation (the route-census gate → `route-census.ts`). Shape: `RouteCensusEntry` with a strict disposition enum in `src/lib/arbora-api/route-census.ts`. Test: `src/lib/arbora-api/__tests__/route-census.test.ts::refuses a generated-operation row with no owning operation named`. | Verified by `route-census.test.ts` asserting the refusal and disposition-enum behavior. |
| `OVERSTORY-API-R003.2` | **Route-census data file and lint rule (remaining).** The remaining scope has two parts. One is a checked-in route census data file populated for every `api_extensions.py` domain route family. The other is an architecture lint rule that runs in CI and rejects any new unclassified domain route. Caller chain: the CI architecture lint → `src/lib/arbora-api/route-census.json` → the routes in `agent/overstory/api_extensions.py`. Shape: one census row per domain route in `route-census.json`, validated by the `route-census.ts` model. Test: `src/lib/arbora-api/__tests__/route-census-lint.test.ts::rejects a newly introduced domain route until it is inventoried`. | Route-census and contract tests plus the lint rule running in continuous integration confirm no unclassified domain route remains. |
| `OVERSTORY-API-R004` | **Each request carries its own correlation id.** The host mints a fresh correlation id for each HTTP request and WebSocket connection without an inbound `x-correlation-id`. An ambient id bound on the serving thread never enters a request. Caller chain: an inbound HTTP or WebSocket request → `RequestObservabilityMiddleware` in `agent/overstory/observability.py` → the request context. Shape: a fresh id minted per request in the middleware, reusing the existing correlation binding. Test: `agent/overstory/__tests__/test_observability.py::test_http_request_gets_one_access_log_line_and_a_correlation_header`. | An observability test binds an ambient id and serves two requests. It confirms two distinct ids that differ from the ambient one. |
| `OVERSTORY-API-R006` | **Generated TypeScript client from a pinned Arbora schema.** Overstory generates its TypeScript types and client from a pinned Arbora v1 API schema and digest. The client exposes one invoke adapter and a stable error envelope for all callers. Caller chain: `pnpm run arbora:client:gen` → `src/lib/arbora-api/generated/openapi.json` and `schema.ts` → `invoke.ts` used by every caller. Shape: the generated `schema.ts` plus one `invoke` adapter and a stable error envelope. Test: `src/lib/arbora-api/__tests__/invoke.test.ts::preserves a structured server refusal and rejects malformed success`. | A regeneration-diff check plus contract tests confirm the generated client matches the pinned schema and envelope. |
| `OVERSTORY-API-R007` | **Typed operations preserve preview-confirm-step-up for effects.** Decisions, Markets/apps pages, WebMCP tools and the console confirmation flow in overstory call typed Arbora operations through the generated client. They preserve the preview, confirmation and step-up sequence. That sequence is required before any side-effecting action runs. Caller chain: decision, Markets, WebMCP and console pages → `invoke.ts` → the host → the served Arbora operation with preview, confirm and step-up. Shape: preview and `plan_ref` handling in `src/lib/arbora-api/invoke.ts` and `identity.ts::confirmedStepUpUrl`. Test: `src/components/views/__tests__/ConsoleConfirmView.test.tsx::rejects malformed plan refs without a network call`. | Positive and negative effect tests exercise the preview, confirm and step-up sequence end to end. |
| `OVERSTORY-API-R008` | **Ontology, graph, Atlas and object-set operations preserve tenant semantics (rollup).** Split by code root into `OVERSTORY-API-R008.1` (ontology), `OVERSTORY-API-R008.2` (graph), `OVERSTORY-API-R008.3` (Atlas) and `OVERSTORY-API-R008.4` (object-set), producer first. This row is LANDED only when all four children are LANDED. | Each child's own verification row; see below. |
| `OVERSTORY-API-R008.1` | **Ontology reads and writes use typed Arbora operations with preserved tenant semantics.** Overstory's ontology callers call typed Arbora operations. The callers cover schema graph, catalogue, import/export, registry types and interfaces. They live in `agent/overstory/api_extensions.py` and their `src` counterparts. The operations preserve tenant scoping, purpose context, cursor pagination and existing error semantics. Caller chain: ontology views → `src/lib/arbora-api/ontology.ts` → `invoke.ts` → the served Arbora operation. Shape: typed ontology wrappers in `src/lib/arbora-api/ontology.ts` replacing the ontology blocks in `agent/overstory/api_extensions.py`. Test: `src/lib/arbora-api/__tests__/ontology.test.ts::validates a well-shaped class page`. | Cross-surface fixtures and a browser test confirm ontology-read parity after migration. |
| `OVERSTORY-API-R008.2` | **Graph reads and writes use typed Arbora operations with preserved tenant semantics.** Overstory's graph callers in `agent/overstory/api_extensions.py` and their `src` counterparts call typed Arbora operations that preserve tenant scoping, purpose context, cursor pagination and existing error semantics. Caller chain: graph views → the generated client → `invoke.ts` → the served Arbora operation. Shape: typed graph wrappers beside `ontology.ts`, reusing its validation helpers. Test: `src/lib/arbora-api/__tests__/ontology.test.ts::maps a forbidden scope to a forbidden reply without leaking detail`. | Cross-surface fixtures and a browser test confirm graph-read/write parity after migration. |
| `OVERSTORY-API-R008.3` | **Atlas reads and writes use typed Arbora operations with preserved tenant semantics.** Overstory's Atlas callers in `agent/overstory/api_extensions.py` and their `src` counterparts call typed Arbora operations that preserve tenant scoping, purpose context, cursor pagination and existing error semantics. Caller chain: Atlas views → the generated client → `invoke.ts` → the served Arbora operation. Shape: typed Atlas wrappers beside `ontology.ts`, reusing its validation helpers. Test: `src/lib/arbora-api/__tests__/ontology.test.ts::maps an unmounted registry route to unavailable, not a thrown error`. | Cross-surface fixtures and a browser test confirm Atlas parity after migration. |
| `OVERSTORY-API-R008.4` | **Object-set reads and writes use typed Arbora operations with preserved tenant semantics.** Overstory's object-set callers (`ObjectExplorerView`, `ObjectView`) in `agent/overstory/api_extensions.py` and their `src` counterparts call typed Arbora operations that preserve tenant scoping, purpose context, cursor pagination and existing error semantics. Caller chain: `ObjectExplorerView` and `ObjectView` → the generated client → `invoke.ts` → the served Arbora operation. Shape: typed object-set wrappers beside `ontology.ts`, reusing its validation helpers. Test: `src/lib/arbora-api/__tests__/ontology.test.ts::rejects a malformed class result before any view can render it`. | Cross-surface fixtures and a browser test confirm object-set parity after migration. |
| `OVERSTORY-API-R009` | **Prompts, SDD, knowledge base, sessions and goals migrate to typed calls.** Overstory's prompts, SDD, knowledge base, sessions, goals, MCP servers/tools and model-management features call typed Arbora operations in place of host-owned routes. Caller chain: prompt, SDD, knowledge-base, session, goal, MCP and model pages → the generated client → `invoke.ts`. Shape: one census row per migrated route family in `route-census.json`. Test: `src/lib/arbora-api/__tests__/route-census-lint.test.ts::covers every current enhanced host route with a validated row`. | A route census and contract tests confirm each family is covered by a generated operation. |
| `OVERSTORY-API-R010` | **Host drops direct internal imports once replacement operations are proven.** Overstory removes direct internal imports and domain route handlers from its host once the replacement Arbora operations are proven. It keeps only an explicitly inventoried set of browser-local endpoints. Caller chain: the architecture gate → `src/lib/arbora-api/route-census.ts` and `route-census.json` → the host routes in `agent/overstory/api_extensions.py`. Shape: a census row per route with its disposition, reusing `RouteCensusEntry`. Test: `src/lib/arbora-api/__tests__/route-census-lint.test.ts::rejects a newly introduced domain route until it is inventoried`. | A static dependency check and route-census gate confirm no forbidden import or unlisted domain route remains. |
| `OVERSTORY-API-R011` | **Shared auth and streaming are preserved without exposing a service bearer.** Overstory preserves shared authentication, credential delegation, streaming and cancel behavior, and error handling across the migration. It never exposes an Arbora service bearer token to browser JavaScript. | Host integration tests and adversarial browser tests confirm the bearer is never exposed and behavior is preserved. |
| `OVERSTORY-API-R005` | **Failure logs carry a sanitized typed error code.** `_log_failure` in api_extensions.py logs the operation label, exception type and an `error_code`. The code comes from the `engine_error_code` or `code` attribute. A value that is not an upper-case token of 64 characters or fewer is logged as `none`. Message text never reaches the log. Caller chain: a failing host route → `_log_failure` in `agent/overstory/api_extensions.py` → the log line. Shape: an `error_code` field limited to an upper-case token of 64 characters or fewer. Test: `tests/test_log_failure_error_code.py::test_typed_engine_code_is_logged`. | tests/test_log_failure_error_code.py confirms `ACCESS_DENIED` is logged, malformed codes log `none`, and message text is absent. |
| `OVERSTORY-API-R011.1` | **Host composition without an engine.** The WebUI factory holds no graph engine. A host composes its routes through `application_composer` on the real factory. Graph data comes only from Arbora served operations; a route without one answers 501 `not_available`. Injection grants no identity or session authority. Caller chain: the host entry point → `application_composer` on the real factory in `agent/overstory/server.py` → the served operation or a 501 `not_available`. Shape: route composition through `application_composer` with no graph engine held. Test: `agent/overstory/__tests__/test_served_operations.py::test_routes_without_a_served_operation_answer_not_available`. | Host-seam tests prove the served-operation calls and the `not_available` answers through the real factory. |
| `OVERSTORY-API-R011.2` | **Chat preserves explicit conversation and admitted task identities.** The browser sends its selected conversation identity from the first turn. Its cache, draft and SDK state are scoped to the observed caller and tenant. The host does not derive identity from prompt text. It rejects conflicting conversation identities and propagates only explicit Arbora task, context, run and trace references through message metadata. A trace reference is not interpreted as a graph trace ID. | Mounted chat transport and host streaming tests prove first-turn identity, conversation isolation, missing and conflicting identity, and exact returned references. This does not establish durable resume or trace retrieval. |

| `OVERSTORY-API-R011.2.1` | **Conversation and admitted-identity source preservation.** Bind selected conversation identity in mounted transport source. Scope cache, draft and SDK state to the observed caller and tenant. Reject conflicting conversation identities. Preserve only explicit returned task, context, run and trace references in host message metadata. Do not derive identity from prompt text or treat a trace reference as a graph trace ID. Caller chain: the mounted chat transport → the host streaming route → message metadata. Shape: conversation-owner scoping in the chat transport, reusing `conversation-owner` helpers. Test: `src/lib/__tests__/chat-transport.test.ts::retains the committed binding across sequential send and reconnect on one transport`. | Source fixtures cover first-turn identity, isolation, malformed and conflicting identity, and exact returned references. These fixtures do not qualify the installed composed browser-to-Arbora path. |
| `OVERSTORY-API-R011.2.2` | **Composed conversation identity qualification.** Retain every parent R011.2 obligation beyond source fixture coverage. Qualify the mounted browser transport and host streaming path against the installed Arbora provider. Caller chain: the browser chat transport → the host streaming path → the installed Arbora provider. Shape: the same transport and host seams as R011.2.1, qualified end to end. Test: planned `e2e/chat-identity-served.spec.ts::first_turn_identity_through_composed_path`. | Planned: Prove first-turn identity, observed caller and tenant isolation, missing and conflicting identity, and exact returned references through the composed path. Keep durable resume and trace retrieval separate. |
