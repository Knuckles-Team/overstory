# scripts/asset-kit — Blender authoring pipeline for the city asset kit

The original GLB families under `public/city-assets/kit/` are generated by
these scripts in Blender through the `blender` MCP server (blender-mcp).
The full playbook — setup, conventions, export contract, review protocol,
pitfall log — is
`agent/overstory/skills/overstory-development/references/blender-asset-pipeline.md`.

- `kitlib.py` — the shared factory: Caribbean coastal palette,
  origin-centred low-poly primitives, the robust (baked) join, and the
  `family()` pipeline with export-time QA — join-mismatch guard,
  design-intent size guards, budget checks, bottom-centre pivot
  normalisation — plus the adaptive review shelf.
- `stage01_roads.py` … `stage08_marine.py` — one builder module per
  category (roads, street props, landscape, vehicles, architecture,
  buildings, furnished interiors, marine). Each exports a `SPECS` table of
  `(family-id, builder, category[, expect extents])` and one builder per
  family.
- `blendermcp_startup.py` — start the blender-mcp addon server on
  127.0.0.1:9876 at Blender launch (Blender must run in GUI mode).

Rebuilding: launch Blender in GUI mode with the startup script, connect the
MCP server, then clear the scene, add the review sun, iterate each
module's `SPECS` through `kitlib.family(fid, fn, cat, expect=...)`, add each
result to the shelf, and review with multi-angle renders before dumping
reports. `kitlib.OUT_ROOT` points at `public/city-assets/kit/`. Any change
to shared code re-exports every family it touches; catalog digests and the
asset lock are regenerated from the final files.
